# FinSIGHT — Banking Customer Churn Prediction

> **Running the dashboard app?** See [README_APP.md](README_APP.md). This file documents the training scripts.

**Member 1: EDA, Data Cleaning, Preprocessing, KNN and Logistic Regression**

FinSIGHT is a college Machine Learning Lab mini-project. It predicts whether a bank customer might leave the bank (**churn**) using the Kaggle Churn Modelling dataset. This folder contains Member 1's completed code, written in a simple, practical-style approach. The KNN and Logistic Regression algorithms are implemented from scratch, without calling the ready-made scikit-learn classifiers.

## 1. Dataset and target

- Dataset: `data/Churn_Modelling.csv` — 10,000 customer records, originally 14 columns.
- Target: `Exited` (`0` = stayed, `1` = left).
- Not used as prediction features: `RowNumber`, `CustomerId`, `Surname`.
- The remaining 10 original input features are: `CreditScore`, `Geography`, `Gender`, `Age`, `Tenure`, `Balance`, `NumOfProducts`, `HasCrCard`, `IsActiveMember`, `EstimatedSalary`.
- EDA found 7,963 stayed (79.63%) and 2,037 left (20.37%), with no missing values or duplicate rows.

## 3. Setup and run in VS Code

1. Extract/open the **FinSIGHT_VSCode** folder in VS Code (not just its `src` folder).
2. Open **Terminal → New Terminal**.
3. Install the libraries (only needed once per environment):

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. On the **first run**, generate the EDA outputs:

   ```powershell
   python src/FULL_EDA.py
   ```

5. Train and evaluate **improved KNN**:

   ```powershell
   python src/KNN.py
   ```

6. Train and evaluate **Logistic Regression**:

   ```powershell
   python src/Logistic_Regression.py
   ```

Run these commands **from the main `FinSIGHT_VSCode` folder**. You can run KNN and Logistic Regression separately once EDA has produced the output files. When an EDA/model graph appears, close the chart window to let the script continue to the next graph or save step.

## 4. What each Python file does

### `src/FULL_EDA.py` — Tasks 2–5

- Loads the CSV and performs Exploratory Data Analysis (EDA): first records, shape, information, summary statistics, class distribution, graphs, correlations and churn-group averages.
- Checks for missing values, duplicates and invalid data.
- Removes `RowNumber`, `CustomerId`, `Surname` **from modelling data only** (original CSV remains unchanged).
- One-hot encodes `Geography` and `Gender`, producing 13 encoded input columns.
- Makes one **stratified 80:20 split** with `random_state=42`: 8,000 training rows and 2,000 testing rows.
- Fits `StandardScaler` to the **training** data only; transforms testing data using that same fitted scaler.
- Saves encoded and scaled feature CSVs, target CSVs, the fitted scaler and feature-name references for reuse.

### `src/KNN.py` — Improved K-Nearest Neighbors, from scratch

- Uses the saved EDA split and manually calculates Euclidean distances between customers.
- Uses nearby customers to estimate churn, based on a vote or distance-weighted vote.
- Tests additional K values, voting methods, prediction thresholds, StandardScaler/MinMaxScaler, random undersampling and feature subsets.
- Chooses settings using a separate **training-only validation** subset and F1-score (not by tuning on the test set).
- Re-trains the chosen configuration, tests on the 2,000 held-out customers, and prints metrics and charts.
- Outputs are saved in `outputs/knn_improved/`.

### `src/Logistic_Regression.py` — Logistic Regression, from scratch

- Loads **encoded (not previously scaled)** EDA files, because this script applies training-only scaling itself.
- Uses a linear score, **sigmoid** function and **gradient descent** to learn customer churn likelihood.
- Tests learning rates, L2 regularization, class balancing and prediction thresholds using training-only validation.
- Fits the selected settings using all 8,000 training rows, then evaluates the held-out 2,000 test rows.
- Saves metrics, predictions, validation trials and a `.pkl` containing model weights, bias, fitted scaler, feature order and chosen threshold.
- Outputs are saved in `outputs/logistic_results/`.

**Important:** `logistic_model.pkl` is a dictionary of model parameters and preprocessing references. It is not a ready-made sklearn classifier; application integration must apply the stored preprocessing and sigmoid calculation correctly. `KNN.py` currently saves evaluation/prediction CSVs rather than a deployable fitted KNN model file.

## 6. Verified model results (held-out test set)

All metrics are for the **Exited = 1 (churn)** class where applicable.

| Metric | Improved KNN | Logistic Regression |
|---|---:|---:|
| Accuracy | 74.20% | 77.85% |
| Precision | 42.65% | 46.33% |
| Recall | 77.64% | 55.77% |
| F1-score | 55.05% | 50.61% |
| ROC-AUC | 0.8389 | 0.7773 |

- KNN detects **316 / 407** actual churners but incorrectly flags **425** staying customers.
- Logistic Regression detects **227 / 407** actual churners and incorrectly flags **263** staying customers.
- Higher recall helps catch more potential churners; higher precision means fewer false alerts. Accuracy alone is misleading because the dataset has many more stayers than churners.

These are demonstration results on this dataset, not guarantees for real banking use. The same held-out test set has already been viewed when comparing model versions; for an unbiased final comparison after any further tuning, use fresh independent data or a properly planned evaluation protocol.

## 8. Common problems

- **FileNotFoundError for `outputs/*.csv`:** Run `python src/FULL_EDA.py` first from the project folder.
- **ModuleNotFoundError:** Run `python -m pip install -r requirements.txt` in the selected Python environment.
- **Program appears stuck:** KNN can take time because it manually calculates customer distances. Some plots also block execution until their window is closed.
- **Different results after edits:** Check that the dataset, `random_state=42`, train/test split, validation protocol and input column order have not been changed.

See `MEMBER1_SIMPLE_EXPLANATION.txt` for a beginner-friendly explanation of everything completed in Member 1.
